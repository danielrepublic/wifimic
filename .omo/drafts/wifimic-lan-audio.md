## Decisions (with rationale)

- Retain Rust and refactor from micdriver rather than introduce a second language or media stack; both hosts already have the pinned compiler and the source contains the required PCM, UDP, WASAPI, tray, deployment, and test foundations.
- Treat Linux session control as a required redesign: client Start/Restart sends a start request and keeps a heartbeat; client Exit/disconnect makes the server stop `parec` and return to idle without stopping `wifimic-server`.
- Preserve packet ordering, bounded jitter, session identifiers, sender-IP filtering, and diagnostics from micdriver; they are latency/safety behaviour rather than unneeded generalization.
- Retain the current fixed 497-byte/5 ms packet contract initially, but add a protocol-contract test that explains and verifies the existing 484-byte PCM-frame invariant before reuse; 48 kHz × 5 ms × 16-bit mono ordinarily suggests 480 bytes, so this must not remain an undocumented assumption.
- Interpret "startup" as starting the interactive client after the sole user's logon. The requested tray icon is technically incompatible with a standalone Session-0 service.
- Use TDD: every protocol/control-state change is introduced with automated tests first; deployment and real two-host audio checks remain agent-executed acceptance evidence.
- Create the canonical private GitHub repository from this workspace with the authenticated local `gh` account before documenting clone-based deployment; do not assume a pre-existing remote.
- If the Windows client cannot send an explicit stop, the Linux server stops capture after 30 seconds without a valid client heartbeat. This is the user-selected tolerance for transient network loss.
- Fix the transport and renderer contract at 48 kHz, 16-bit PCM mono. The Linux source may expose two channels, but the server selects/downmixes to mono before the existing fixed-frame path; no stereo protocol expansion is in scope.
- On capture-source/PipeWire failure, keep `wifimic-server` alive, emit a typed operational error, and retry capture every 5 seconds only while a client heartbeat remains valid. Automatically resume the same active session when capture succeeds.
- Retain Linux logs through journald; rotate Windows diagnostic logs under `%LOCALAPPDATA%\wifimic-client` so no more than 7 days or 10 MiB survives. Logs must never contain raw audio samples.
- Read-only baseline measurement found both hosts on 5 GHz 802.11ac Wi-Fi via the router. Windows-to-Linux ICMP had 0% loss but 1–174 ms RTT (21 ms average); Linux-to-Windows ICMP is firewall-blocked, so the plan must measure UDP application latency after the scoped 6902 rule exists rather than infer it from ping.
- The end-to-end audio latency acceptance target is P95 ≤ 200 ms, measured by the application over the actual UDP 6902 path after firewall deployment.
- Replace micdriver's fixed 20 ms jitter buffer with an adaptive 40–200 ms buffer: start at 40 ms, grow during loss/late-frame bursts to protect continuous audio, then decay cautiously after stability returns.
- Pin Linux capture to `alsa_input.pci-0000_00_1b.0.analog-stereo`; never silently substitute a default or alternate source. A missing source follows the selected retry-and-log behavior.
- Scope UDP 6902 firewall rules and application-level accepted peers to the two fixed hosts only; no encryption is added, but unrelated LAN devices are rejected without latency cost.
- Updates are explicit manual commands targeting a Git tag or commit. Each installer preserves the last known-good executable/configuration, validates the new service/client health, and automatically rolls back on failure; no background self-update exists.
- Tray Exit stops only the current Windows process and immediately sends a stop request; it does not disable the Scheduled Task, so the client starts again at the next user logon.
- If the server is offline or cannot be reached, keep the client/tray process alive and retry its idempotent start/heartbeat exchange every 5 seconds; recovery must resume streaming automatically without requiring Restart.
- The old micdriver code is reference material, not a copy target. wifimic must improve code quality through explicit state-machine boundaries, typed errors, strict linting, small cohesive modules, protocol invariants, and tests that preserve the agreed external behavior.
- Preserve agreed external behavior while restructuring internals; quality work must not add unrequested product features or change the public two-machine deployment/lifecycle contract.
- Interpret `main_draft.md`'s literal `sudo systemctl start wifimic` as describing the always-on boot behavior conceptually, not a literal root-level command to implement verbatim: PipeWire capture must run inside the user's own session bus, which a root/system-level systemd unit cannot reach, so the actual mechanism is `systemctl --user enable --now wifimic-server` plus `loginctl enable-linger daniel` (matching `main_draft.md:12`'s "the Linux service is always on" requirement). `docs/deployment-linux.md` explains this to the user so they never need to run the literal `sudo` command.
